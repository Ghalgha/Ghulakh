# Текущий статус

Дата фиксации: 2026-11-10.

## Реализовано в репозитории

- Rust workspace и общие типы управляющего протокола;
- QUIC-сервер на TLS 1.3 с ALPN `ghulakh/1`;
- аутентификация по индивидуальным credentials, хранящимся на сервере в виде SHA-256 digest;
- constant-time сравнение digest и случайный идентификатор сессии;
- ограничение размера управляющих сообщений и проверка версии протокола;
- минимальный Android-проект и объявление Android VpnService;
- документация архитектуры, протокола и модели угроз;
- CI workflow для форматирования, тестов и Clippy.

## Не реализовано

- безопасный API provisioning/rotation/revocation устройств;
- постоянное хранилище сессий;
- QUIC DATAGRAM для пользовательских пакетов;
- TUN на сервере, маршрутизация и IP forwarding;
- Android QUIC-клиент и интеграция с Rust transport core;
- автоматическая проверка сертификата/публичного ключа на Android;
- интеграционные сетевые тесты и fuzzing.

## Ограничения безопасности

Серверная аутентификация использует файл SHA-256 digest высокоэнтропийных credentials. Файл не должен содержать исходные credentials. Каждому устройству нужен отдельный случайный секрет; отзыв выполняется удалением соответствующего digest и перезапуском сервера. Управление credentials пока ручное.

Клиентская проверка TLS ещё не реализована в Android. Пользовательские IP-пакеты пока не туннелируются. Сервер нельзя считать готовым VPN-сервисом.

## Локальная конфигурация

Задать переменные окружения:

- `GHULAKH_CREDENTIAL_HASHES` — файл с одним SHA-256 digest в hex на строку;
- `GHULAKH_TLS_CERT` — путь к PEM certificate chain;
- `GHULAKH_TLS_KEY` — путь к PEM private key;
- `GHULAKH_QUIC_BIND` — UDP bind address, по умолчанию `0.0.0.0:4433`.

Для создания credential используйте криптографический генератор случайных чисел. Передавайте клиенту исходный секрет защищённым каналом, а в файл сервера помещайте только его SHA-256 digest. Не добавляйте credentials или приватные ключи в Git.
