# Текущий статус

Дата фиксации: 2026-11-10.

## Реализовано в репозитории

- Rust workspace, общие типы управляющего протокола и отдельное транспортное ядро QUIC-клиента;
- QUIC-клиент с проверкой заданного DER trust anchor и имени сервера, аутентификацией, ping и API отправки/приёма IP-датаграмм;
- QUIC-сервер на TLS 1.3 с ALPN `ghulakh/1` (Quinn 0.11.12 с явно зафиксированным quinn-proto 0.11.19);
- аутентификация по индивидуальным credentials, хранящимся на сервере в виде SHA-256 digest;
- утилита выпуска 256-битных device credentials с записью только digest в серверный файл;
- constant-time сравнение digest и случайный идентификатор сессии;
- ограничения размера управляющих сообщений, request ID и credentials;
- ограничение активных QUIC-соединений до 1024 на процесс, максимум 16 двунаправленных потоков и запрет ненужных однонаправленных потоков;
- бинарный формат QUIC DATAGRAM v1 и проверка базовой структуры IPv4/IPv6 пакетов с тестами;
- серверный приём QUIC DATAGRAM с ограниченным буфером и параллельной обработкой управляющих потоков;
- назначение клиентам индивидуальных IPv4-адресов из пула 10.77.0.0/16;
- опциональный серверный IPv4 TUN с очередью на 512 пакетов, обратной маршрутизацией по адресу назначения и проверкой исходного адреса клиента;
- двухступенчатый fail-closed handshake: Android получает отдельные флаги готовности TUN и административного подтверждения forwarding; без обоих флагов локальные VPN-маршруты не устанавливаются;
- egress ACL блокирует частные, loopback, link-local, multicast, broadcast, CGNAT, IETF protocol-assignment, documentation и benchmarking диапазоны по умолчанию;
- серверные unit-тесты на отклонение датаграмм до аутентификации, повреждённых пакетов и проверку индивидуальных credentials;
- loopback integration test: QUIC-клиент устанавливает TLS-соединение, проходит аутентификацию, выполняет ping и отправляет IP-датаграмму, которую сервер принимает;
- проверка закрытия QUIC-клиента при ожидающем чтении датаграммы: ожидающий receive завершается ошибкой после close (CI run `42842727513` успешен);
- тайм-аут чтения управляющего потока;
- Kotlin JNI facade и native Rust QUIC library с cross-compilation для Android ABI в CI;
- Android UI для параметров сервера, импорта X.509 trust anchor и проверки QUIC-соединения;
- шифрование credential и DER-сертификата AES-GCM ключом Android Keystore;
- Android VpnService с IPv4 TUN, full-tunnel IPv4-маршрутом, fail-closed IPv6-маршрутом и двунаправленным обменом пакетами через JNI;
- Android VPN worker завершает сессию при неожиданном EOF TUN или пустом результате native receive вместо оставления второго потока в бесконечном ожидании (изменение ожидает CI);
- защита исходящего QUIC UDP-сокета через VpnService.protect до установки TUN-маршрутов;
- документация архитектуры, протокола, модели угроз и эксплуатации сервера.

## Ограничения безопасности

Серверная аутентификация использует файл SHA-256 digest высокоэнтропийных credentials. Исходные секреты не сохраняются сервером. Каждому устройству нужен отдельный случайный секрет; отзыв выполняется удалением соответствующего digest и перезапуском сервера.

Android-приложение создаёт TUN только после успешной аутентификации и подтверждения сервером, что IPv4 TUN включён и администратор явно подтвердил готовность IP forwarding/NAT/firewall. QUIC UDP-сокет исключается из VPN-маршрутов через VpnService.protect. IPv6 направляется в TUN и отбрасывается сервером, чтобы не допустить обхода туннеля. Автоматическое восстановление после смены сети и адаптация MTU пока не реализованы. Сервер пересылает разрешённые IPv4-пакеты только при `GHULAKH_TUN_ENABLED=true` и явном `GHULAKH_FORWARDING_ENABLED=true`; оба параметра по умолчанию выключены. IP forwarding, NAT и firewall сервер автоматически не меняет. IPv6 и доступ к частным сетям по умолчанию запрещены. Сервер нельзя считать готовым VPN-сервисом.

## Конфигурация

- `GHULAKH_CREDENTIAL_HASHES` — файл с одним SHA-256 digest в hex на строку;
- `GHULAKH_TLS_CERT` — путь к PEM certificate chain;
- `GHULAKH_TLS_KEY` — путь к PEM private key;
- `GHULAKH_QUIC_BIND` — UDP bind address, по умолчанию `0.0.0.0:4433`;
- `GHULAKH_TUN_ENABLED` — `true` для включения серверного TUN, по умолчанию `false`;
- `GHULAKH_TUN_NAME` — имя TUN-интерфейса, по умолчанию `ghulakh0`;
- `GHULAKH_FORWARDING_ENABLED` — административное подтверждение настройки IP forwarding/NAT/firewall; по умолчанию `false`.

Подробности выпуска credentials, настройки TUN и системного forwarding — в [SERVER_OPERATIONS.md](SERVER_OPERATIONS.md).
