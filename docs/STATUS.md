# Текущий статус

Дата фиксации: 2026-11-10.

## Реализовано в репозитории

- Rust workspace, общие типы управляющего протокола и отдельное транспортное ядро QUIC-клиента;
- QUIC-клиент с проверкой заданного DER trust anchor и имени сервера, аутентификацией, ping и API отправки/приёма IP-датаграмм;
- QUIC-сервер на TLS 1.3 с ALPN `ghulakh/1` (Quinn 0.11.12 с явно зафиксированным quinn-proto 0.11.19);
- аутентификация по индивидуальным credentials, хранящимся на сервере в виде SHA-256 digest;
- утилита выпуска 256-битных device credentials с записью только digest в серверный файл;
- constant-time сравнение digest и случайный идентификатор сессии;
- ограничения размера управляющих сообщений, request ID и credentials;
- ограничение активных QUIC-соединений до 1024 на процесс, максимум 16 двунаправленных потоков и запрет ненужных однонаправленных потоков;
- бинарный формат QUIC DATAGRAM v1 и проверка базовой структуры IPv4/IPv6 пакетов с тестами;
- серверный приём QUIC DATAGRAM с ограниченным буфером и параллельной обработкой управляющих потоков;
- серверные unit-тесты на отклонение датаграмм до аутентификации, повреждённых пакетов и проверку индивидуальных credentials;
- loopback integration test: QUIC-клиент устанавливает TLS-соединение, проходит аутентификацию, выполняет ping и отправляет IP-датаграмму, которую сервер принимает;
- тайм-аут чтения управляющего потока;
- Kotlin JNI facade и native Rust QUIC library с cross-compilation для Android ABI в CI;
- Android UI с запросом системного разрешения VPN;
- CI workflow для Rust checks, аудита зависимостей, Android native cross-build и Android debug build;
- документация архитектуры, протокола, модели угроз и эксплуатации сервера.

## Не реализовано

- API provisioning/rotation/revocation и горячее обновление реестра устройств;
- постоянное хранилище сессий;
- маршрутизация пользовательских пакетов и передача их в TUN пока отключены;
- TUN на сервере, маршрутизация и IP forwarding;
- интеграция JNI с Android VpnService, управление TUN-потоками и безопасное хранение credentials в Android Keystore;
- проверка сертификата/публичного ключа в Android;
- дополнительные сетевые тесты под нагрузкой, проверка потерь/смены сети и fuzzing.

## Ограничения безопасности

Серверная аутентификация использует файл SHA-256 digest высокоэнтропийных credentials. Исходные секреты не сохраняются сервером. Каждому устройству нужен отдельный случайный секрет; отзыв выполняется удалением соответствующего digest и перезапуском сервера.

Android-приложение может запросить системное разрешение VPN, но пока не запускает туннель и не меняет маршруты. JNI facade уже определён, однако вызовы из VpnService и хранение credentials/certificate в Android Keystore ещё не реализованы. Клиентская проверка TLS ещё не реализована. Пользовательские IP-пакеты принимаются по QUIC DATAGRAM только после аутентификации и проходят проверку формата, но затем отбрасываются: серверный TUN и маршрутизация отсутствуют. Сервер нельзя считать готовым VPN-сервисом.

## Конфигурация

- `GHULAKH_CREDENTIAL_HASHES` — файл с одним SHA-256 digest в hex на строку;
- `GHULAKH_TLS_CERT` — путь к PEM certificate chain;
- `GHULAKH_TLS_KEY` — путь к PEM private key;
- `GHULAKH_QUIC_BIND` — UDP bind address, по умолчанию `0.0.0.0:4433`.

Подробности выпуска credentials и запуска — в [SERVER_OPERATIONS.md](SERVER_OPERATIONS.md).
