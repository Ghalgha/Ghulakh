# Протокол: начальная спецификация

Статус: draft, не является стабильным wire-стандартом.

## Транспортный уровень

- QUIC и TLS 1.3 реализуют шифрование, целостность, согласование ключей и защиту транспорта от replay.
- ALPN: `ghulakh/1`.
- Клиент обязан проверить цепочку сертификата и имя сервера либо закреплённый доверенный ключ.
- Отключение проверки сертификата запрещено.
- 0-RTT для изменяющих состояние команд отключён.

## Управляющий поток v1

Каждое управляющее сообщение передаётся в отдельном QUIC bidirectional stream. Клиент закрывает свою сторону отправки после одного JSON envelope; сервер читает не более 16 KiB, проверяет структуру и отвечает в том же stream.

Envelope:

```json
{
  "version": 1,
  "message": {
    "type": "client_hello",
    "body": {
      "credential": "<per-device random secret>",
      "request_id": "client-generated-id"
    }
  }
}
```

Поддерживаемые типы:
- `client_hello` — аутентификация клиента;
- `server_hello` — подтверждение аутентификации и выдача случайного идентификатора сессии;
- `ping` / `pong` — проверка управляющего канала;
- `close` — закрытие соединения.

В каждом сообщении обязателен непустой `request_id`. Неизвестная версия, некорректный JSON, неожиданный тип сообщения и превышение лимита приводят к отказу соединения.

## Идентификация

Каждое устройство должно получать уникальный случайный credential. Сервер хранит только SHA-256 digest высокоэнтропийного credential; сравнение выполняется с constant-time equality. Текущий серверный прототип поддерживает один bootstrap credential из переменной окружения. Это временное ограничение, а не целевая модель управления устройствами.

Credential передаётся только внутри аутентифицированного TLS 1.3/QUIC соединения. Его запрещено помещать в URL, логи, crash reports или открытые конфигурационные файлы.

## Датаграммы пользовательских данных

QUIC DATAGRAM пока не реализован. Планируемый формат должен включать версию и тип полезной нагрузки. Максимальный размер определяется безопасным MTU и не должен приводить к IP-фрагментации QUIC-пакетов. Точные поля будут зафиксированы до реализации совместимых клиентов и сервера.

## Совместимость

Изменения wire-формата сопровождаются увеличением версии или согласованным расширением. Неизвестные критические расширения отклоняются.
